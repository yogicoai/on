일일 퍼널 점검 탭 추가 요청

전사 대시보드에 자사몰·스마트스토어의 일별 퍼널 목표 대비 실적을 확인하는 탭을 추가하려 합니다. 화면은 완성된 독립 HTML로 전달하므로, 1단계는 삽입만으로 끝납니다.

요청일 2026-08-27 전달 파일 자사몰_스마트스토어_일일퍼널점검.html (68KB) 외부 의존성 없음

요청 배경

월 순매출 목표를 퍼널 단계별 목표로 환산해 두었고, 이를 매일 아침 전일 실적과 대조해 어느 단계가 부족한지 보고 그날의 액션을 정하려 합니다. 기간을 지정하면 프로모션 구간 단위로도 같은 점검이 가능합니다.

현재는 이프두·스마트스토어 통계를 수동으로 내려받아 화면을 갱신하는 구조입니다. 이 수동 단계를 없애는 것이 이번 요청의 핵심입니다.

구현 단계

아래 순서는 실제 의존 관계입니다. 1단계만으로도 화면은 동작하며, 2단계가 자동 갱신을 담당합니다. 3단계는 선택입니다.

STEP 1

탭 추가 & 화면 삽입

필수

전사 대시보드에 탭을 하나 추가하고, 전달드린 HTML을 iframe으로 불러 주세요.

<iframe src="/dashboards/funnel_daily.html"
        id="funnelDaily"
        style="width:100%; border:0; display:block;"></iframe>

직접 병합(코드 복붙)은 피해 주세요. 전달 파일은 전역 CSS 변수(--ink, --card 등)와 흔한 클래스명(.card, .stage)을 사용합니다. 기존 대시보드와 이름이 겹치면 양쪽 스타일이 서로 깨집니다. iframe은 문서가 완전히 분리되어 충돌 위험이 없습니다.

높이 처리 — 현재 파일은 자기 높이를 부모에 알리지 않습니다. 둘 중 편한 방식으로 알려 주시면 맞추겠습니다.

  • 고정 높이로 두기 — 탭·기간에 따라 길이가 변해 여백이나 스크롤이 생깁니다
  • postMessage로 높이 전송 — 요청 주시면 전달 파일에 발신 코드를 넣어 드리겠습니다 (권장)

필요 작업 — 탭 1개 추가 + iframe 삽입. 데이터·API 작업 없음.

STEP 2

데이터 자동 갱신

핵심

이번 요청에서 실제 개발이 필요한 부분입니다. 매출 데이터는 이미 대시보드가 보유하고 있으므로, 새로 필요한 것은 퍼널 단계 데이터입니다.

데이터현재 상태요청 사항
자사몰
퍼널 5단계		 이프두에서 수동 다운로드
카페24 API 미제공		 신규 — 이프두에서 일별 수집 → DB 적재
스마트스토어
유입·주문		 스마트스토어 통계 수동 다운로드 신규 — 일별 수집 → DB 적재
순매출
(양 채널)		 대시보드가 이미 보유

월 목표 화면에 하드코딩 관리 화면에서 월별 입력

적재 스키마 — 화면이 요구하는 최소 형태입니다.

funnel_mall_daily   (date, 방문시작, 상품조회, 장바구니조회, 주문서작성, 주문완료)

목표 입력 주기 — 다음 달 목표는 월 시작 1주 전에 확정합니다. 해당 월 1일 전까지 값이 들어와 있으면 됩니다. 반기 단위로 미리 넣어도 동작합니다.

필요 작업 — 수집 배치 2종 + 테이블 3개 + 목표 입력 화면. 갱신은 하루 1회면 충분합니다(전일 확정 데이터만 사용).

STEP 3

네이티브 재구현

선택 · 급하지 않음

iframe 대신 대시보드의 기존 컴포넌트로 다시 그리는 방식입니다. 디자인 통일성은 올라가지만, 1·2단계가 끝나면 실용상 급하지 않습니다. 진행하실 경우 아래 계산 규칙을 그대로 옮겨 주세요.

계산 규칙 — 그대로 유지 필요

월 순매출 목표에서 퍼널 단계 목표를 역산합니다. 비율은 성과가 가장 좋았던 기준월에서 가져왔습니다(자사몰 2025-10, 스마트스토어 2025-11).

자사몰

월 주문완료 = 월순매출목표 ÷ (1 − 취소반품 10%) ÷ 객단가 225,000
월 유입     = 월 주문완료 ÷ 구매전환율 1.9228%
월 상품조회 = 월 유입 × 63.4597%
월 장바구니 = 월 유입 × 4.1919%
월 주문서   = 월 유입 × 3.8490%
일 목표     = 각 월 목표 ÷ 해당 월 일수

검증값 — 8월(1.3억·31일) 기준 일 목표는 유입 1,077 / 상품조회 683 / 장바구니 45.1 / 주문서 41.5 / 주문완료 20.7 / 순매출 4,193,548원입니다.

스마트스토어

월 주문건수 = 월순매출목표 ÷ 건당매출 160,661
월 유입     = 월 주문건수 ÷ 구매율 3.08%
일 목표     = 각 월 목표 ÷ 해당 월 일수

검증값 — 8월(5,600만·31일) 기준 일 목표는 유입 471 / 주문건수 17.0 / 순매출 1,806,452원입니다.

판정 규칙

  • 달성률 = 실적 ÷ 목표. 100% 이상 정상 / 85~99% 주의 / 85% 미만 미달
  • 월말 예상 = 누적 ÷ 경과일 × 월 일수
  • 기간 목표 = 해당 기간 각 일자의 일 목표 합계. 목표가 등록되지 않은 달이 하루라도 섞이면 달성률을 표시하지 않습니다
  • 달성률 판정은 순매출로만 합니다. 목표가 순매출 기준이기 때문입니다

데이터 정의 주의사항

지표 이름이 같아도 소스마다 정의가 다릅니다. 섞으면 목표 대비 성과가 왜곡됩니다.

이프두 “방문시작” ≠ 카페24 “순방문자”

같은 날 기준으로 13~18% 차이가 일관되게 납니다(세션 기준 vs 중복 제거 방문자). 예: 8/26 이프두 2,161 vs 카페24 1,860.

퍼널 목표 비율이 이프두 정의로 산출되었으므로, 유입 실적도 반드시 이프두 값을 써야 합니다. 카페24 순방문자로 대체하면 전환율이 실제보다 높게 나옵니다.

스마트스토어 “주문건수” — 파일과 DB가 다름

스마트스토어 통계 파일의 주문건수는 DB 결제완료건수의 약 0.75배입니다. 벤치마크(구매율 3.08%, 건당매출 160,661원)는 파일 기준으로 산출했으므로, DB 건수로 바꾸면 벤치마크도 함께 재산정해야 합니다.

매출도 두 종류입니다 — 파일 매출은 취소 반영 전, DB 순매출은 취소·반품 제외입니다. 8/23 기준 347만원 vs 333만원.

취소·반품율 기준이 채널별로 다름

자사몰은 금액 기준(건수 파악 불가), 스마트스토어는 건수 기준(부분취소 존재)으로 추산합니다. 두 채널의 취소율을 직접 비교하면 안 됩니다.

장바구니 → 주문서 전환율이 100%를 넘을 수 있음

버그가 아닙니다. 장바구니를 거치지 않고 바로구매로 주문서에 진입한 고객이 포함되기 때문입니다. 전체 603일 중 35.7%의 날에서 100%를 넘었고 중앙값은 95.4%입니다. 상한 처리하지 말아 주세요.
