## 설계 원칙 — 무엇을 저장하고 무엇을 조회하는가

이 자료에는 **성과 수치가 들어 있지 않습니다.** 의도적입니다.

| 계층 | 성격 | 내용 |
|---|---|---|
| L1 정의 | **저장** | promo_id, 기간, 몰, 대상상품, 할인율, 혜택, method |
| L2 맥락 | **저장** | 공동구매·외부행사 캘린더, 할인방식 전환 이력, 베이스라인 지정 |
| L3 성과 | **조회** | 매출·리프트·믹스·유입·광고·반품 — 기존 MCP 도구가 실시간 계산 |

**이유**

1. 수치는 소급 변경됩니다. 반품·취소는 나중에 확정되고 광고 데이터는 매체 API 재적재로 바뀝니다. 저장하는 순간 대시보드와 어긋나는 제2의 진실이 생깁니다.
2. 같은 이름의 지표가 도구마다 기준이 다릅니다. 자사몰 매출만 해도 `cafe24_analysis`는 공동구매를 포함하고 `marketing_period_compare`는 제외합니다. 2026-08 기준 **40,459,905원 vs 17,984,623원**으로 2배 넘게 벌어집니다. 어느 쪽을 저장해도 절반은 틀립니다.
3. 계산 규칙이 바뀝니다. 베이스라인 기준만 해도 이번 분석에서 세 번 바뀌었습니다.

L1·L2는 MCP가 스스로 만들 수 없는 정보이고, L3는 이미 MCP가 매일 갱신하고 있습니다.

## `promotions[]` 필드

행 단위는 **프로모션 × 몰**입니다. 기존 MCP 저장 방식과 동일합니다. 프로모션 69건 × 진행 몰 = 198행.

### 식별·기간

| 필드 | 타입 | 설명 |
|---|---|---|
| `promo_id` | string | `YYYYMM-NN` 형식. 예 `202607-01`. 전체 고유 |
| `campaign_id` | string | `YYYYMM` 또는 `YYYYMMB`(같은 달 2차 캠페인). 예 `202607B`=10주년 |
| `mall` | enum | `자사몰` / `스마트스토어` / `오프라인` |
| `name` | string | 프로모션명 |
| `promo_type` | enum | `전사` / `단기특가` / `IP기획전` / `액세서리` / `시즌` |
| `start` `end` | date | 할인 적용 기간. **연장이 있었으면 최종 확정일** |
| `original_end` | date\|null | 연장 전 원래 종료일. 예 블랙프라이데이 `2025-11-30`→`2025-12-01` |
| `days` | int | `end - start + 1` |

### 집계 방식

| 필드 | 값 | 설명 |
|---|---|---|
| `method` | `상품매칭(전제품)` / `상품매칭` / `혼합` / `쿠폰` | **`상품매칭(전제품)`은 신설 요청 값**(요청 1번) |
| `discount_apply_mode` | `다운로드쿠폰` / `즉시할인` | 자사몰은 **2026-07 프로모션부터 즉시할인**. 스마트스토어·오프라인은 전 기간 즉시할인 |
| `coupon_trackable` | bool\|null | 쿠폰명 매핑이 되는 구간인지. 자사몰만 해당하며 `2026-06`만 `true` |

### 대상 상품

```json
"target": {
  "scope": "전제품" | "제품군" | "품목",
  "include": [ { "raw": "표기명", "mode": "...", ... } ],
  "exclude": [ ... ]
}
```

`include`/`exclude` 항목의 `mode`는 세 가지입니다.

| mode | 구조 | 해석 |
|---|---|---|
| `item` | `{ mode:"item", item:"카카오프렌즈 드롭" }` | ERP 품목명 직접 지정. 하위 규격(색상) 전부 포함 |
| `rule` | `{ mode:"rule", match:{ namePrefix:[...], nameContains:[...], nameEquals:[...], group:[...] } }` | 조건식. 모든 조건은 **OR**로 평가 |
| `set` | `{ mode:"set", components:["냅 엑스","코지보 트래블"] }` | 세트 상품. 구성품 동시 구매 |

**`scope`가 `전제품`이면** `include`는 비어 있습니다. 카탈로그 전체에서 `exclude`를 뺀 것으로 해석해 주십시오.

### 할인율

```json
"discount": { "S":10, "P":20, "PP":15, "accessory":null, "cover":null, "bead":null, "raw":{...} }
```

`S`/`P`/`PP`는 충전재 등급(스탠다드·프리미엄·프리미엄플러스)입니다. 등급별 값이 없고 전체 단일 할인이면 세 값이 같습니다. `raw`에 원본 구조를 그대로 두었으니 특수 케이스(`halfdeal`, `sofa`, `ottoman` 등)는 여기서 확인하십시오.

`special_price[]`는 단가 특가입니다. `{ product, price, rate }`.

### 조건 태그 — 성과 예측용

```json
"tags": {
  "discount_band": "20%", "max_discount": 20, "season": "여름",
  "scope": "전제품", "ip": ["카카오프렌즈"],
  "confounder": ["공동구매"], "ad_boost": true
}
```

| 태그 | 값 | 산출 |
|---|---|---|
| `discount_band` | `할인없음`/`10%이하`/`15%`/`20%`/`30%`/`30%초과` | 해당 프로모션의 최대 할인율 기준 |
| `season` | `설`·`봄`·`여름`·`추석`·`블랙프라이데이` 등 17종 | 프로모션명 키워드 → 캠페인 대표명 → 시작월 순으로 판정 |
| `ip` | `디즈니`/`스타워즈`/`카카오프렌즈` 배열 | 대상상품·프로모션명에서 추출 |
| `confounder` | `공동구매`/`외부행사` 배열 | **기간이 겹치는 교란요인**. 비어 있으면 깨끗한 구간 |
| `ad_boost` | bool | 소속 캠페인의 광고비가 베이스라인 대비 +20% 초과 |

**이 태그가 예측 질의의 전제 조건입니다.** "전 제품 10% + 봄 + 공동구매 없음 + 광고 증액 없음" 조건으로 과거 사례를 찾아 그때그때 실적을 계산하는 방식이 됩니다.

### 베이스라인

```json
"campaign": {
  "rep_promo":"202607-01", "rep_start":"2026-07-03", "rep_end":"2026-07-12",
  "baseline_start":"2026-06-23", "baseline_end":"2026-07-02",
  "baseline_clean_pct":100, "yoy_start":"2025-07-03", "yoy_end":"2025-07-12"
}
```

- `baseline_*` — 직전 동일 일수 구간
- `baseline_clean_pct` — 그 구간 중 **다른 프로모션이 없던 날의 비율**. 낮을수록 비교가 오염됨
- `yoy_*` — 전년 동기. `null`이면 데이터 범위 밖(2024년은 오프라인·광고·유입 데이터 없음)

> **주의** 624일 중 프로모션 진행일이 자사몰 기준 484일(77.6%)입니다. 2025년은 무프로모션이 38일(10.4%)뿐이라 대부분의 베이스라인이 "다른 프로모션 기간"입니다. `baseline_clean_pct`를 반드시 함께 노출해 주십시오.

기획 할인율과 대조해 **실효 할인율**을 산출하는 데 씁니다.

## `events[]` — 교란요인 캘린더

공동구매 11건 + 외부행사 6건.

```json
{ "kind":"공동구매", "start":"2026-08-26", "end":"2026-08-28",
  "channel":"자사몰", "name":"민에듀 공동구매",
  "overlaps_campaign":["202608"], "overlaps_baseline":["202609"] }
```

**왜 필요한가**

- **공동구매**는 회원가입 후에만 구매 가능하도록 상시 세팅돼 있습니다. 진행 기간의 유입·신규가입이 구조적으로 증가합니다. 그런데 매출은 이카운트 기준으로 공동구매를 제외하므로 **분모가 어긋납니다** — 매출은 빼고 회원가입은 더한 상태가 됩니다.
- **외부행사**는 현장 회원가입 이벤트를 붙이는 경우가 있습니다. 2026 영등포 봄꽃축제(4/3~4/7)는 **경품 선지급 후 가입 요청** 방식으로 5일간 신규가입 3,554명을 모았습니다. 캠페인 전체 3,867명의 91.9%입니다. 같은 행사인 2025년은 가입 이벤트가 없어 1.65배에 그쳤습니다.

**22개 캠페인 중 15개가 겹칩니다.** 프로모션 조회 시 이 캘린더를 자동 대조해 경고를 붙여 주십시오.

> 원본 일정표의 2025년 라벨 행은 날짜 일련번호가 +365일 밀려 있어 보정했습니다. MCP 상품태그 4건과 대조해 확인했고, 원본 파일도 수정 완료했습니다.

## `product_map`

ERP 품목 3,053 규격 / 471 품목명.

```json
"products": {
  "카카오프렌즈 드롭": { "erp_codes":["...","..."], "online_codes":["..."],
                        "groups":["Sofa(소파)"], "has_epp_variant":true }
}
```

**병합 규칙** — ERP 품목명의 `(EPP)`·`(HRF)` 표기는 **동일 상품으로 병합**했습니다. 2026-10 통합 예정이라는 담당자 확인에 따른 것으로, 150개 품목이 해당됩니다.

**`aliases`** — 기획 시트 표기 → ERP 품목명 (22건)

`KF드롭`→`카카오프렌즈 드롭`, `SW슬림`→`스타워즈 슬림`, `트레이보 X`→`트레이보 엑스`, `문필로우`→`문 필로우` 등

주의할 것 — `미키버블`·`미니버블`·`스탠다드 버블`·`도날드허거`는 ERP에서 **별도 품목이 아니라 `디즈니 버블`·`디즈니 허거`의 규격(색상)** 입니다.

**`rules`** — 묶음 표현 → 조건식 (22건)

`줄라 전제품`→`namePrefix:["줄라"]`, `커버 전품목`→`nameContains:["커버"]` 등. 개별 코드로 나열하지 않은 이유는 신제품이 추가될 때마다 틀어지기 때문입니다.

특수 케이스 — `냅`·`냅 엑스`는 온라인 판매 코드가 `냅 로고`·`냅 엑스 로고`입니다. 로고 없는 코드는 온라인 미등록이라 조건식으로 양쪽을 모두 포함했습니다.

## 개발자 확인 요청 5건

### 1. `method`에 `상품매칭(전제품)` 신설 — 최우선

현재 MCP는 자사몰을 **연결쿠폰 실사용 기준**으로 집계합니다. 그런데

- 자사몰은 **2026-07 프로모션부터 즉시할인** 세팅으로 전환됐습니다(담당자 확인)
- 실측 결과 쿠폰명 매핑 커버리지가 2026-07 이후 **0%**입니다
- 스마트스토어는 **처음부터 즉시할인**이었습니다

즉 현재 구조로는 자사몰·스마트스토어 **모두 매출이 0**으로 집계됩니다. 실제로 MCP에 등록된 「7월 전사프로모션 [요기보 Week]」의 매출이 0원입니다.

### 2. 쿠폰 기준 등록분 4건 재집계

2026-04~06에 쿠폰 기준으로 등록된 건들의 포착률이 제각각입니다.

| 프로모션 | MCP 쿠폰기준 | 실제 자사몰 매출 | 포착률 |
|---|---|---|---|
| 요기보 스프링 페스타 | 44,085,968원 | 63,285,344원 | 70% |
| 요기보 원더랜드 | 31,262,185원 | 51,166,766원 | 61% |
| 요기보 감사제 | 8,478,615원 | 39,766,311원 | **21%** |

편차가 커서 프로모션 간 비교가 불가능합니다. 상품매칭으로 재집계해야 합니다.

### 3. 상품매칭 시 판매 이력 필터

ERP 품목 3,053건의 `사용구분`이 **전부 YES**라 미사용 코드를 구분할 수 없습니다. 목록으로 관리하면 유지보수가 안 되므로, 매칭 시 **"최근 12개월 판매 이력이 있는 코드만"** 자동 필터를 걸어 주십시오. 단종 코드와 오프라인 전용 코드가 함께 해결됩니다.

### 4. `target` 해석 규칙

위 「대상 상품」 절의 `item`/`rule`/`set` 3가지 mode 처리. `scope="전제품"`은 카탈로그 전체 − `exclude`로 해석.

### 5. 기존 등록분과 기간 불일치 — 덮어쓰지 말 것

| 프로모션 | MCP 등록 | 기획(본 자료) |
|---|---|---|
| COMFORT BEYOND WORDS | 01-09 ~ **02-08** | 01-09 ~ **01-25** |
| SWEET HOLIDAY PARTY | 02-09 ~ **03-08** | 02-09 ~ **02-22** |
| FOR KIDS & PETS | 03-09 ~ **03-31** | 03-09 ~ **03-23** |
| 요기보 원더랜드 | 05-01 ~ **05-18** | 05-01 ~ **05-17** |

MCP는 이벤트 페이지 노출 기간, 본 자료는 할인 적용 기간으로 추정됩니다. 어느 쪽을 기준으로 할지 결정이 필요하며 **병합 처리**해 주십시오. `mcp_existing_name` 필드로 대조할 수 있습니다.

## 데이터 검증 이력

생성 전 전수 검증을 수행했습니다. **오류 0건**.

- promo_id 69건 고유 / 날짜 형식·순서·범위 / 채널 값 / 할인율 범위(0~100)
- price_detail 74행의 promo 참조 무결성 / 할인가 ≤ 정가 / 표기 할인율 vs 계산 할인율
- 캠페인 22개의 대표기간 = 대표 프로모션 기간 / 베이스라인 길이 = 캠페인 길이 / 베이스라인·캠페인 비중첩
- 품목 매핑 85개 표기 전부 해결(미해결 0)
- MCP 원본과 12개 값 무작위 대조 — 전사 오류 없음

잔여 경고 3건은 모두 **공동구매 잔여주문·재결제**로 확인된 정상 건입니다(202601 오늘의집 찬솜맘 재결제 1건, 202606 찬솜맘 6/1~3 잔여, 202507B 하늘이네 앵콜 7/17 이후 잔여).
